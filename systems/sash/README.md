# SASH zk-inference-prover

Adapter for [`sg-ai-safety-hub/zk-inference-prover`](https://github.com/sg-ai-safety-hub/zk-inference-prover) at commit `eb95bfa887299d1637550228d42086c27cbb2b3b` (RFC-0005). This page maps each subcommand onto upstream's tools (RFC-0005 README requirements 1 to 4, 6 and 7) and records what upstream states about the grid of proofs and how the benchmark counts it. Every fact links upstream at that commit, or the companion results repository `sg-ai-safety-hub/zk-inference-results` at `11decec3c0b62c707618aab5deb82750b355d202`. Where upstream is silent, this page says not stated (AGENTS.md rule 9).

What an accepted proof establishes, under which assumptions, and which edges it binds is in the claim card, [`claim.yaml`](claim.yaml) (RFC-0002), unreviewed until a SASH system maintainer reviews it.

## Grid geometry and proof release

### What one proof is

- One segment is "one transformer layer applied to one block of `S` token positions with a context of `C` earlier positions, or the language-model head applied to one block. A sequence is proved as a grid of such segments, and `boundary-grid` checks that the segments fit together" ([statement.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/docs/statement.md#L3-L6)). "Every recorded run has `S = 512`" ([GLOSSARY.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/GLOSSARY.md#L7-L9)).
- The context of a block is a whole number of blocks: the grid rejects a `C` that is not a multiple of `S` ([boundary.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1285-L1305)), and the extractor refuses a ragged last block ([extract.py](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/harness/witness/extract.py#L715-L721)).
- The head is proved over the last prompt block and the generated block ([decision of 2026-09-08](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/docs/decisions/2026-09-08-the-head-is-proved-over-the-last-prompt-block.md#L5-L11), [plan.py](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/harness/witness/plan.py#L230-L238)).
- Prompt and continuation positions are proved alike: "the loop already proves a prompt chunk as readily as a decode one" ([chunks.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/chunks.rs#L63-L70)). `boundary-grid` checks a prompt position's id against the prompt and a generated position's id against the previous position's proved argmax ([boundary.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1148-L1156)). The README's phrase "a STARK prover for the decode step" ([README.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/README.md#L3-L4)) predates this.

### The two v0.1 shapes

| Workload shape | Upstream geometry |
|---|---|
| 4,096 prompt + 512 continuation positions | recorded: `"context": 4096, "s": 512, "positions": 4608, "blocks": 9, "layers": 32, "segments": 290, "head_blocks": "7,8"` ([headline run config](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/runs/2026-09-09-headline-c4096-h100/config.json#L1-L7)); "a grid of 290 segments over 32 layers" ([decision of 2026-09-09](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/docs/decisions/2026-09-09-the-verifier-derives-the-shape-root.md#L37-L40)). 9 blocks of 32 layer segments plus 2 head segments is 290. |
| 1,024 prompt + 64 continuation positions | not stated: upstream has no run, plan or driver for this shape. Every recorded run sets the continuation to one block of `S` positions; at `S = 64` that would be 17 blocks and 546 segments, an arithmetic consequence of that convention, not an upstream statement. |

### When proofs are written

- `compose-chunks --ser-dir` writes each segment's three files (`<tag>.fixed.json`, `<tag>.claims.json`, `<tag>.proof.json`) as soon as that segment is proved ([chunks.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/chunks.rs#L570-L575), [cli.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/cli.rs#L1484-L1500)).
- The segments are verified only after the loop: "**Nothing is proved until everything is.** `rows` holds every chunk's `Composed` *and* its serialized bytes until the loop is over, because the verifier runs afterwards on purpose" ([chunks.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/chunks.rs#L73-L79)).
- `boundary-grid --verify --prompt` reads the serialized files of every segment, verifies each proof, derives each shape root from the published calibration, and checks every layer and token link and every position's id ([boundary.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1489-L1531), [#L1445-L1477](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1445-L1477)). It exits 0 only when all of that holds, and 1 otherwise ([boundary.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1120-L1124)).

## Subcommand mapping

Upstream ships no single command that turns a model and a prompt into a proved grid. Its recorded H100 runs are made by a job script in the results repository, [`sequence-job.sh`](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/lib/sequence-job.sh), configured by [`headline-c4096.sh`](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/headline-c4096.sh#L44-L93), and its published commitment is made by [`model-commitment.sh`](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/model-commitment.sh#L137-L144). The adapter runs the same commands with the same arguments. Every Python step runs as upstream runs it, `uv run --project /src/harness --no-group cpu --group cuda python ...` ([driver.sh](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/lib/driver.sh#L264-L280)), with the harness environment `ZK_MODEL=/models ZK_DEVICE=cuda ZK_THREADS=<n> ZK_OUT=/io/state/zk-out` ([common.py](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/harness/witness/common.py#L12-L18)).

The configuration is the recorded one, verbatim from `headline-c4096.sh`: quantization spec `y-delay-vw12`; shared flags `--round even --numbits 9 --z-hi-bits 7 --variants intexp --head-groups 16,8,8 --tight-table`; layer flags `--round even --diagonal-block` and the five reductions `--gkr-key-tiles --gkr-dequant --gkr-residual-stream --gkr-freivalds --gkr-attnout`; head flags the five reductions; head dump at layer 16; the head over the last prompt block and the generated block; 64 segments per proving process; `ZK_PIPELINE=1`. No skip flag appears anywhere. The block length `S` is the workload's output length, so the continuation is one block, as in every recorded run.

### `verify`

`zk-prover-simd boundary-grid --dir <proof_dir> --plan <proof_dir>/plan.txt --expect-layer-links N --expect-token-links M --verify --prompt prompt.json --verify-calibration model-roots.json --expect-model-roots model-roots.json`: the recorded grid ([sequence-job.sh](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/lib/sequence-job.sh#L404-L414)) with the published commitment the model-commitment campaign compares against ([model-commitment.sh](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/model-commitment.sh#L199-L220)). `--verify-calibration` is required beside `--verify` ([boundary.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1205-L1220), [prover/README.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/README.md#L32-L59)). The link counts come from the commit record, not from the proof: `B * (32 - 1) + 2` on the layer axis and `(B - 1) * 32` on the token axis ([headline-c4096.sh](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/headline-c4096.sh#L106-L114)), so a plan with segments left out fails the counts. The prompt file is `{"ids": request}`. The verifier never sees the weights and runs on the SIMD backend, as upstream's grid does.

The grid checks every generated id against the argmax a head segment proved, but it is not given the claimed output. The adapter therefore also compares `claimed_output` with `tok_in` of the generated block's layer-0 statement, `B<B-1>L0.fixed.json`, which `verify_composed` pins to its proof ([boundary.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1148-L1156)).

## Verdict mapping

`boundary-grid` has "exit status 0 only when every implied link ran and chained on its own axis, every tag sits where its statement says it sits, every position's id is the prompt's or the previous position's proved argmax, the pinned counts (if given) are met, and -- under `--verify` -- every chunk proof verifies; 1 otherwise, after the JSON is written" ([boundary.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1102-L1124)). The adapter reads that JSON (`result.verified`, `result.tokens`, `result.all_chain`, `result.failures`).

| Upstream signal | Verdict |
|---|---|
| exit 0; `verified.run > 0`, `verified.accepted == verified.run` and `verified.all`; `tokens.all`; `all_chain`; and `claimed_output` equal to the generated block's stated ids | `accept` |
| exit 0 and all of the above, but `claimed_output` differs | `reject` |
| exit 1 and `verified.accepted < verified.run`: a segment proof rejected | `reject` |
| exit 1 and `all_chain` false, `tokens.all` false or `failures` not empty: the grid check failed | `reject` |
| anything else: no JSON (a panic, exit 101; a refused call, exit 1 with no JSON), JSON that contradicts the exit status, nothing verified, or a statement the adapter cannot read | `no_verdict` |

`raw_exit_code` is the grid's exit status and `raw_last_line` the last non-empty line of its stderr (of its stdout when stderr is empty), at most 4,096 bytes. `invalid_call` is never returned: upstream has no exit status for a malformed proof. A `verify` whose verifier files do not hash to `commitment_id` exits non-zero before the grid runs.

| `prover_files` | `/io/state/zk-out/attn_ranges.json`, the attention calibration the extractor quantizes K, V and Q with ([extract.py](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/harness/witness/extract.py#L636-L642), [ppl.py](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/harness/witness/ppl.py#L26)), and `/io/state/zk-out/tokens.npz`, whose `calib` slice it is computed from ([common.py](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/harness/witness/common.py#L280-L291)) |

Upstream states that the calibration is "a property of the weights and the quantization variant and not of the prover", that a model root "is keyed by the layer alone and is a function of the model", and that a shape-root row holds only for the plan it was derived over ([driver.sh](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/lib/driver.sh#L143-L150), [#L207-L213](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/lib/driver.sh#L207-L213)). That is why the commitment is derived once, over upstream's corpus, and checked against any prompt's grid with `--expect-model-roots` and `--verify-calibration`, and why `--expect-pre-roots` is not used. "The commitment is a function of the weights as this harness loads and quantizes them. Nothing here compares those weights against a published checkpoint" ([REPRODUCE.md](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/REPRODUCE.md#L1449-L1452)); the benchmark's model digest (RFC-0014) is that check.

## Backend

The adapter proves on the CUDA backend, as every recorded H100 sequence run does ([sequence-job.sh](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/lib/sequence-job.sh#L370), [REPRODUCE.md](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/REPRODUCE.md#L281-L285)), and runs emission, `model-roots` and `boundary-grid` on the SIMD backend, as upstream does. It never falls back: a failed kernel build, a missing architecture or a fallback line stops `prove`.

The CUDA binary built into the image cannot prove an 8B segment as it stands. Upstream's CUDA backend "proves through device kernels generated per segment shape, so the job emits the kernels for every distinct shape in the plan into one store, installs them into the vendored library and rebuilds" ([REPRODUCE.md](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/REPRODUCE.md#L281-L285)); "The CUDA backend's build is the same commit with the generated kernel store installed into the vendored library, which is how a device build is made at all" ([prover/README.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/README.md#L250-L255)). The shapes come from the plan, and the plan from witnesses extracted on the card, so the store cannot be built with the image: `prove` builds it, in a copy of the source, whenever the plan's shapes change. Upstream's prover README and kernels README say a fresh CUDA build "evaluates constraints on the CPU" until the kernels are installed ([prover/README.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/README.md#L17-L19), [prover/kernels/README.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/kernels/README.md#L3-L4)). At the pin, under the CUDA default `ZK_DEVICE_WITNESS_GEN_KEY_TILE=1` a key tile's columns are on the device ([compose.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/compose.rs#L6976-L6979)), and for device columns a missing generation kernel panics instead ([devfrac.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/devfrac.rs#L193-L206), [#L293-L298](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/devfrac.rs#L293-L298); the checked-in table is the placeholder [gencudakernels.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/gencudakernels.rs)).

The vendored library also picks its architecture by running `nvidia-smi` before `project()`, and falls back to `89;100;120` when that fails ([CMakeLists.txt](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/nitroo/crates/stwo/src/stwo_cuda/cuda/CMakeLists.txt#L7-L32)); `CUDAARCHS` is "only advisory here" ([on-card.sh](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/tools/gate/on-card.sh#L27-L31), [tools/gate/README.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/tools/gate/README.md#L111-L123)). The image is built without a GPU, so its `libstwo_cuda.a` most likely carries no `sm_90` code. The rebuild in `prove` runs with the card visible and is read back with `cuobjdump`, as upstream's gate does.

## Deviations from upstream's measuring setup

- **The prompt.** `gen_ids` decodes only from upstream's corpus: it reads the prompt from `common.tokens()`, which caches the corpus in `ZK_OUT/tokens.npz` ([gen_ids.py](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/harness/witness/gen_ids.py#L54-L60), [common.py](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/harness/witness/common.py#L280-L291)). Upstream documents no way to decode a given prompt. The adapter writes the job's prompt into that cache as `eval`, keeps upstream's `calib` slice and runs `gen_ids --offset 0`. No upstream source or flag changes, but a cache file is used as an input, which upstream does not document; this needs confirming with upstream before any row is published.
- **The kernel build is inside `prove`.** Upstream emits, installs and rebuilds before its timed loop and does not time it ([REPRODUCE.md](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/REPRODUCE.md#L318-L332)). Here it is part of the `prove` call and is reported as the adapter phase `kernels`. The extraction, outside upstream's `loop` and `whole wall` scopes, is the phase `witness`.
- **The commitment.** Upstream derives `model-roots` over the plan of the sequence it then checks ([model-commitment.sh](https://github.com/sg-ai-safety-hub/zk-inference-results/blob/11decec3c0b62c707618aab5deb82750b355d202/tools/drivers/model-commitment.sh#L13-L20)); here it is derived over a commitment sequence from upstream's corpus, before any prompt is known.
- **The 1,024 + 64 shape** uses blocks of 64 positions; upstream records only `S = 512` (table above).
- **Proof storage.** Upstream keeps serialized proofs on its host; here they are the released proof directory, three files per segment (`<tag>.fixed.json`, `<tag>.claims.json`, `<tag>.proof.json`) and `plan.txt`.
- **Nothing is reused between jobs.** Upstream reuses witnesses, the build and the kernel store across campaigns at one context; each benchmark job starts from an empty `/io/state`.

## Values for `system.yaml`

`system.yaml` declares these values, from the facts above, with the image the images workflow pushed and no system maintainer named yet (RFC-0001 §System inclusion):

```yaml
deterministic_proofs: true
incremental_proofs: false
proofs: {granularity: "segment_grid", tokens_covered: "prompt_plus_output", steady_boundary: "not_observable", steady_approximate: false,
         verify_reads: "all"}
forbidden_flags: ["--unsound-skip-", "--unsound-argmax-lax"]
```

- `proofs.granularity: segment_grid`. One proof in the benchmark's sense is a sequence's whole grid, the unit `boundary-grid` accepts or rejects, released when every segment of it is written (RFC-0005 §system.yaml).
- `proofs.tokens_covered: prompt_plus_output`. A grid proves every prompt and continuation position of its sequence, so one proof covers `prompt_tokens + output_tokens` positions: 4,608 and 1,088 for the two shapes, a function of the shape whatever the block length.
- `incremental_proofs: false` and `proofs.steady_boundary: not_observable`. A job proves one sequence, so its one grid is released once; release times carry no steady-state information, and `prove.steady` is null for SASH rows (INV-ADAPTER-10). Segment files appear one by one, but a segment is not the benchmark's proof.
- `proofs.steady_approximate: false`: no steady scope is reported.
- `proofs.verify_reads: "all"`: `verify` reads every part of the proof directory, so C5, C6 and C8 choose among all of them ([RFC-0008 §Parts the verifier reads](../../rfcs/0008-negative-controls.md#parts-the-verifier-reads)). `boundary-grid --plan` reads `plan.txt` and takes the grid's tags from its `--ser-tag` set ([boundary.rs](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1222-L1224), [#L1060-L1071](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1060-L1071)); for every tag it reads `<tag>.fixed.json` and `<tag>.proof.json` ([#L1250-L1252](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1250-L1252)), and under `--verify` `<tag>.claims.json` as well ([#L1492-L1495](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/prover/src/boundary.rs#L1492-L1495)). Every segment file in the directory is one `compose-chunks` wrote for a tag of that plan (§`prove`), and the adapter also reads `B<B-1>L0.fixed.json` for the claimed output check (§`verify`).
- `deterministic_proofs: true`. Upstream gates every change on reproducing recorded proof digests on both backends: "A change that should not alter the proof reproduces the recorded digests on both backends before it merges" ([README.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/README.md#L60-L66)).
- `forbidden_flags`: the `--unsound-skip-` prefix and `--unsound-argmax-lax`, each of which unbinds or weakens an edge of the binding table ([statement.md](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/docs/statement.md#L19-L36), [#L153-L160](https://github.com/sg-ai-safety-hub/zk-inference-prover/blob/eb95bfa887299d1637550228d42086c27cbb2b3b/docs/statement.md#L153-L160)).

Build steps, as upstream: `cargo build --release --locked` for `zk-prover-simd`, then `cargo build --release --locked -p zk-prover --features cuda` for `zk-prover-cuda`, with `CUDAARCHS=90` (sm_90, the H100). Differences from upstream's Dockerfile, none of which touches upstream source (AGENTS.md rule 1):

- Rust comes from the checksummed standalone tarball instead of `rustup`, so the fetch stage checks it against `inputs.lock` (B2). `curl` is not installed, since only `rustup` needed it.
- Crates are fetched with `cargo fetch --locked` in the fetch stage and built `--offline` (B3); Cargo.lock's checksums verify them. Some crate archives carry files readable by their owner only (`fnv` 1.0.7); the fetch stage makes `/opt/cargo` readable by all, since `prove` builds the CUDA library as the adapter user.
- The harness's CUDA torch group is installed instead of the default CPU group, as upstream documents for a CUDA host.
- The source is added with `git` at the pinned commit; the fetch stage checks `git rev-parse HEAD` (INV-ADAPTER-2) and the sha256 of `git archive --format=tar HEAD` against `inputs.lock`.
- Ubuntu packages are pinned to exact versions (PIN-5) from the archive; the Ubuntu snapshot service, which would keep them installable after an update, returned HTTP 503 for every date on 2026-11-04.
