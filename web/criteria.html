    Criteria

    Weights hidden

    Does the checker learn nothing about the weights?

    Yes
    The documentation says the weights stay hidden from the checker in the default use, naming no leak beyond public settings.
    Partly
    Hidden with a stated limit: a named leak, hiding shown only for one policy or setting, or hiding optional per circuit.
    No
    The documentation says the checker sees the weights or hiding is off, or the design gives the checker the weights.
    Not stated
    No statement about hiding the weights from the checker, or we have not recorded it yet.

    Hiding from the host operator (an enclave) is not this property.

    Model bound

    Is each checked token tied to the committed weights?

    Yes
    The documentation says a passing check ties each checked token to the committed weights exactly, in the default or expected use.
    Partly
    Tied with a stated limit: only under one of several policies, within a tolerance or bound, or shown only in empirical tests.
    No
    The documentation says outputs are not tied to any weights, or nothing is checked.
    Not stated
    Not stated, or we have not recorded it yet.

    Which real, named model the commitment is: FlashProve and SASH both say that stays outside their proof; it does not change the state.

    Whole output proved

    Does one check cover every output token of a request?

    Yes
    The documentation says one check, or one joined set of checks, covers the prompt and every output token of a request.
    Partly
    One check covers a stated part: the positions the client names, one segment, or one disputed step.
    No
    The documentation says no output token is checked, or nothing is checked.
    Not stated
    Not stated (for example a graph run whose output tokens are not named), or we have not recorded it yet.

    Which requests get a proof (sampling, post-hoc proving) is a deployment choice, not what one check covers. The text before tokenizing and after detokenizing: FlashProve and SASH both say it is outside their proof.

    Formally verified

    Is the security argument checked by a proof assistant?

    Yes
    The documentation says the protocol's soundness is proved in a proof assistant (Lean, Coq, Isabelle or similar).
    Partly
    Machine-checked for a stated part only: one component, or a weaker statement than the one the system makes.
    No
    The documentation says it is not machine-checked: planned only, or the evidence named is review and tests.
    Not stated
    Not stated, or we have not recorded it yet.

    Whether the programs users run are proved: no row claims it.

    Security level

    Is a soundness level stated, and proven?

    Yes
    The documentation states a numeric soundness bound and says it is proven, by hand or by machine, under named assumptions.
    Partly
    A numeric level is stated but called conjectured, or stated only in code or configuration, or for part of the system.
    No
    The documentation says the settings give no meaningful soundness, for example a test-only setting.
    Not stated
    No level stated, or we have not recorded it yet.

    The state shows only whether a level is stated and proven. The level is judged for the protocol, as the documentation states it; whether the programs a checker runs meet it is not shown: no row proves its programs.

    No trusted party

    Does a check hold without trusting a chip maker, a setup ceremony or an honest party?

    Yes
    The documentation says a check rests on cryptography alone or needs no trusted setup, and names no chip or party to trust.
    Partly
    The documentation states a trusted input or condition that its proved statement does not cover: a setup file, public files the user must grant were fixed before the hash (a provider who tuned them is outside the statement), or one honest party among several.
    No
    The check is a hardware attestation verified against a chip maker's keys, or nothing is checked and the provider is trusted.
    Not stated
    Not stated, or we have not recorded it yet.

    Trust every row shares is not counted: the checker's own computer, compiler and verifier build, and where the commitment or the weights come from (see Model bound).
