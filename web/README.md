# The public site

The public site at www.inferenceproofs.ai, its design named "Made of words". Draft criteria, needs an RFC (RFC-0001). The site shows only the benchmark's own runs. **Every benchmark result on it is a placeholder until v0.1 is frozen (#146)**: the pages are built from a placeholder release of synthetic runs, no real measurement (see Models), and served with `noindex`. The pages do not mark them, because the published site will only ever show real runs. Names, pins, claim cards, criteria rows, model sizes and workloads are the real ones.

The rules the site follows (pages, order, labels, script, narrow screens) and where it does not meet them yet are in [RFC-0009 §Site](../rfcs/0009-results-and-publication.md#site).

Static pages written by `iproofs site build` from the newest frozen release (see Data), served at clean addresses: `/` (the overview, `index.html`), `/flashprove` and `/sash` (one page per benchmarked system), `/reference` (the two references), `/criteria` (what each state means for each property), `/release` (the release record), `/sponsors` (sponsors and conflicts), `/targets` (only when the release evaluates a target) and the 404 page.

## Build and check

From the repository root:

```
PYTHONPATH=harness/tests uv run python -m fixtures.placeholder_release --site web   # until v0.1 (#146): the placeholder release, frozen in a temporary tree, then `iproofs site build --out web` there
uv run iproofs site build                # from v0.1 on: the pages from releases/*/index.json into web/ (until then it stops with a configuration error)
uv run pytest web -q                     # sort keys, preview cards, search, the loader, breakpoints: the committed files against a fresh build and hand-computed cases
```

The build writes the pages, 404.html, search.json, vercel.json, the card sources in og/, the fonts block in words.css and the contrast table below; `--out DIR` writes a complete site elsewhere (static assets copied). It never deletes a file: a page it no longer writes stops the build. From this folder:

```
PLAYWRIGHT_MODULE=<path to playwright/index.mjs> node og.mjs   # when a card source changed; then rebuild, so the pages name the new pictures
python3 -I serve.py                      # http://127.0.0.1:4440/ as on Vercel: the deployed files only, clean addresses, redirects, headers (CSP included), 404
PLAYWRIGHT_MODULE=<path to playwright/index.mjs> \
AXE_MODULE=<path to @axe-core/playwright/dist/index.mjs> \
BASE=http://127.0.0.1:4440/ node shoot.mjs    # screenshots and checks into shots/ (shots/checks.txt)
```

`PLAYWRIGHT_MODULE` and `AXE_MODULE` default to the package names `playwright` and `@axe-core/playwright`. Locally they can be installed under `web/.tools/` (ignored by git): `npm i --prefix .tools playwright @axe-core/playwright`. `node peek.mjs <page> <width> <height> <out.png> [1 for full page] [script]` takes one screenshot. `shoot.mjs` exits non-zero when any check fails.

## Deploy

www.inferenceproofs.ai serves this folder from Vercel's Git integration (the Vercel project's Root Directory is `web`). The build writes `vercel.json`, since parts of it come from the build:

- `ignoreCommand`: `git diff --quiet HEAD^ HEAD -- .` skips a deployment when the commit (on main, the merge commit against its first parent) does not change this folder.
- `buildCommand`: no build on Vercel; it copies the committed pages, `words.css`, `words.js`, the pictures and icon in `og/` and the fonts in `fonts/` into `public/`, the only folder served. The data, scripts, card sources, screenshots and README are not.
- `cleanUrls` and `trailingSlash: false`: `/flashprove` serves `flashprove.html`; `/flashprove.html` and `/flashprove/` redirect to it. Every link on the pages is root-relative and clean, so no click costs a redirect and the 404 page works at any depth. `/system` (an older address) redirects to the first system page.
- Headers on every response: `noindex` while the results are placeholders, a Content-Security-Policy that allows only this site's own files plus the one inline script by its sha256 (computed by the build), `X-Frame-Options: DENY`, a Permissions-Policy, `nosniff` and a referrer policy.
- Caching: `words.css` and `words.js` are linked with `?v=` and the first 12 hex of their sha256, the pictures likewise, and each font file carries its hash in its name; all four get a one-year immutable cache. Pages revalidate on every visit.

The pages are served as committed, so `.github/workflows/site.yml` holds them to the build: on every pull request and push to main that touches an input of the build (`releases/`, `systems/`, `workloads/`, `targets/`, `results/`, `reference/`, `schema/`, `rfcs/`, `MAINTAINERS.md`, `LICENSES/`, the harness and its test fixtures, `pyproject.toml`, `uv.lock` or this folder) it rebuilds them with the placeholder command above (`uv run iproofs site build` once v0.1 is frozen), runs `uv run pytest web -q` and fails if any file under `web/` differs from what the build writes, new files included.

## Fonts

Archivo (variable width and weight) and IBM Plex Mono 400, 500 and 600 are served from `fonts/`, not from Google Fonts: no third-party request, no visitor's address sent elsewhere, and text that shows as soon as this site's files arrive. The files are Google Fonts' own Latin and Latin Extended subsets, plus a Plex Mono subset for the arrows (← ↑ → ↓ ↕ ↗), × and ≈ so every arrow is set in the same face. `fonts/faces.json` lists each file with its family, weights, widths and unicode range; each file's name carries the first 10 hex of its sha256, which the build checks (`load_faces` in `draw/chrome.py`). The build writes the `@font-face` rules into `words.css` between its markers and preloads the three most used files. Both fonts are under the SIL Open Font License 1.1 (`fonts/OFL-*.txt`).

## Data

`iproofs site build` reads the newest frozen `releases/*/index.json` and its `release.yaml`, the claim cards, run records (`run.json`, `controls.json`) and replies they name, `systems/*/system.yaml` and `controls.yaml`, `workloads/`, `reference/`, `targets/`, `MAINTAINERS.md`, the RFC file names in `rfcs/`, the criteria file `_data/criteria.json` (RFC-0016) and the display facts `_data/facts.json` (schema `site-facts/1`: names, techniques, licences, repository status, model display names, the models a not-benchmarked system's sources name). `iproofs.site` turns them into one view, with no git call and no clock, so the same files give the same bytes; the renderer (`build.py` and `draw/`) draws that view and opens no data file. Every number on the pages is a value the index stores, printed at 4 significant digits in a reading unit; the renderer words the stored ids (scope, grade, tier, null reasons, failure kinds, units, states, families) through fixed tables and types no number. It stops if a state ink steps less than 1.7:1 from the one below, if a text pair falls under 4.5:1, if `words.css` holds different inks or slice lifts than the ones the build computes with, if a font file's name does not carry its hash, if a reworded phrase is no longer in the criteria or facts file, if a criteria family has no words, if a rule code names an RFC that does not exist, or if `out` holds a page or card source the build no longer writes. The footer pins the committed `criteria.json` by its sha256.

What the pages leave out of the data, or say differently, on purpose:

- The systems' own published figures, outside their claim cards. The benchmark measures. Each state's deciding quote is printed on the system page in its property's entry of "How we read it", verbatim, with its source at the pin; a card's own figures (`quality_gap`) are printed as the card states them, with their sources.
- Every placeholder marking: no MOCK chips and no banner. The placeholder runs are marked by this README, the `noindex` header and "(candidate)" in the footer, which stays until a tracked file records the release's publication.
- RFC rule codes ("RFC-0015 NM-1") never print bare: on plates and in the more-numbers table they become a small "rule ↗" link to the RFC after the sentence's full stop, its code read to screen readers; in home cells and titles they are left out.
- A few criteria phrases are worded for a reader who has not read the RFCs (`PHRASES` in `draw/plates.py`, each checked still to be in the criteria or facts file): the rerun reference is never called "recompute"; the criteria page does not speak of quotes, cards, glyphs or "not copied yet", which the site does not show. An overhead stored as null with `not_measurable_on_profile` reads "Plain serving could not run this model on one H100, so there is no baseline to divide by". A row that names its own basis ("GPU cost per 1,000 positions") prints its value without repeating it.
- Spreads read in words ("3 completed, 1 failed", not "n = 3 runs, n_failed = 1": n counts the completed runs, the failed ones are not in the figure), a per-unit line reads "per proof", raw floats are dropped from titles, a number never wraps away from its unit (nor a count word or a statistic from what it counts), an id, date or model name never breaks at a hyphen, and a "·" separator never starts a line. A missing number's title gives only why it is missing.
- A run record or the release's `index.json` is named by its path, not linked, while the release is a candidate: no tracked file holds them until #146 publishes the release. Once it does, the same places link them at `main`.
- A missing number carries no grade or check: its plate shows why it is missing and where that is recorded, its more-numbers row only why.
- The references: one row per reference on the overview, from its own configurations. What one proof covers reads "Same as the system" (a reference record is an output, not a proof, RFC-0015 REF-2); plain serving's overhead reads "Baseline", the denominator of the ratio, never a typed 1×. A reference whose kept runs all failed shows its counts, "below minimum repetitions" and, where RFC-0015 NM-1 applies, that it is not measurable on the profile's GPU.
- Not benchmarked yet: each system's models in full (never cut mid-phrase), and its status without repeating what the heading or the status already says ("no adapter yet", a second "archived").

## Models

The overview sets one table per model, largest first by the total parameters its workload record states (`workload.model.parameters.total`, then the model's name; `models_by_size` in `draw/overview.py`, which stops the build if two workloads of one model state different totals), then one per workload of that model (RFC-0009 S6), from the workloads the release's configurations ran: the model's native workloads by id, then its closed ones, then its open ones (RFC-0003 §Divisions). There is no table across models (the owner dropped the table of every system on 2026-11-08, #333): each row (one system configuration on one workload and profile) is in exactly one table, its workload's, so a system with one such row is on the overview once, glyph and all. A table across models returns once a figure that compares provers across models can be sorted (RFC-0004 INV-DERIVE-7). Tables of different native workloads side by side (two workloads on one model, or tables of two models) carry the header "Native workloads differ: rows are not a head-to-head comparison" once, above the first of them: the header heads a group that holds the native tables (one group per run of adjacent native tables, should a closed or open table ever come between two). A closed or open table never counts toward it, carries it or sits in its group: it follows the group, and its heading's second line names its workload, its division and the profiles of its rows (`l31-8b-c1024 · closed division · prover-h100`), and rows compare directly within a closed table only. The deployed placeholder holds no closed or open table; the extras build holds one. Within a table the rows go A to Z by system name, then profile id, then the configuration's position in the release's `index.json` (`by_name`). A table holding two rows of one system names each row's configuration beside its pin. The placeholder release holds two tables, each on `prover-h100`: Llama 4 Maverick (400B parameters, 17B active per token, workload `fp-maverick-w1024-b24`) with FlashProve, then Llama 3.1 8B (8.03B parameters, workload `sash-l31-8b-c1024`) with SASH.

**The placeholder release (until v0.1, #146).** `harness/tests/fixtures/placeholder_release.py` builds it in a temporary git tree from copies of the real `schema/`, `reference/`, `rfcs/`, `MAINTAINERS.md`, `LICENSES/`, the tracked files of this folder (less `shots/`), the two workloads and the system directories of FlashProve, SASH and the two references, none of them edited: each prover runs on its own native workload (RFC-0003). The runs are synthetic records of no real run: raw values chosen so the figures keep the digits the site printed before #320, every derived metric computed by `iproofs.derive`, so `iproofs release freeze` passes the real gates G2 to G7 on them. SASH has one failed and one superseded run. The references run on the Maverick workload only and fail every run with kind `resource` (RFC-0015 NM-1), so FlashProve's overhead and agreement rate are null; the placeholder holds no reference run on SASH's workload, so SASH's two figures read "Not recorded in these runs." One proof covers is each system's own count under its `tokens_covered` rule (`tokens_covered_per_proof`, D-STAT over D-TPP), read from the placeholder index like every other figure.

The fixture's test-only cases (`extras=True`: a reply written by no system maintainer, a target, a pending disclosure, an override, a second workload and card, the closed workload `l31-8b-c1024` run by SASH and by `fixture-closed` ("Fixture prover", a copy of SASH's system file, card, criteria and facts rows that exists in no real tree, so the closed table holds the two systems of its class the freeze requires), more runs left out, an unexpected control) build the golden pages under `harness/tests/golden/site/` and never reach this folder.

## Design

Dark ground, paper text. Violet is the benchmark's own frame: the six properties and page titles, never a value or a state. Green, amber, red and grey mean Yes, Partly, No and Not stated, and appear only in the glyph's slots and the state squares. The grey (`--unstated`) has no hue, so it never reads as a fourth state colour. Archivo for display, IBM Plex Mono for data. No cards, shadows or double rules; no helper sentences, taglines or captions.

Narrow screens follow one scale of widths, desktop first as the base rules are. Breakpoints (px): 1240 1180 1099 1000 960 920 760 635 560 400 360 349. `words.css` opens one `@media` block per width, wide to narrow, and sets each selector once in it, so at the same specificity a narrower block overrides a wider one. One block also takes a min-width, one px above a width of the scale, and sits last: 350 to 560 px (a plate's label beside its value); 349 is on the scale only as its lower edge. The hover, reduced-motion, forced-colours and landscape (`max-height`) rules are not width blocks and keep their places; a width inside one (the landscape rule's 960 px) is still a width of the scale. `test_breakpoints.py` checks the blocks against the scale, which this list and the comment at the top of `words.css` both give.

Each system is drawn as the **hex asterisk**: six triangles that make a point-top hexagon, one per property, clockwise from twelve (Weights hidden, Model bound, Whole output checked, Formally verified, Security level, No trusted party), so 1 to 3 sit on the right and 4 to 6 on the left, on a pie's own 60-degree axes. The cuts between the triangles widen toward the centre, so the ground they leave draws an asterisk, the footnote mark that sends a reader to the fine print. Every slot is always filled, Not stated in the grey, so the hexagon is always whole. The glyph is drawn in device pixels (`hex_svg` in `draw/hexagon.py`): gaps and lines are sized for each size, and up to 40 px the centre and the flat sides sit on the pixel grid. In one colour (`mark_svg`, wider cuts so the asterisk leads) it is the logo, the favicon and the touch icon. It was chosen in a study of six directions (hexagon, ring, pinwheel, asterisk, pixel disc, cut pie) judged on reading, brand and fit. The properties carry no numbers anywhere.

### Header and footer

Every link to another site (quote sources, pinned repositories, GitHub, RFC files on GitHub) opens in a new tab, with no opener and no referrer; the site's own links stay in the tab (`new_tab` in `draw/chrome.py`, held by `test_links.py`).

The top bar: the logo (the site's mark, the hex asterisk in violet, and its name; it leads to the overview and marks it as the current page there) and the pages (References, Criteria) at the left, a wide search field (up to 600 px) centred in the room between them and GitHub at the right. Up to 960 px, below the width a centred field needs, the field becomes a search button by GitHub. Up to 960 px the logo, the pages, the button and GitHub share one line; at 560 px and below the logo is its glyph alone and GitHub its mark alone (both names still read aloud), so the line fits down to 320 px. The button opens a sheet over the page: the field over the first line (16 px type, so a phone does not zoom on focus; no autocorrect or capitals; a close button), its results under it, ending above the on-screen keyboard (`--vvh`, from the visual viewport), and the ground ink over the rest. Hiding the keyboard keeps the results; a tap on the sheet outside them, the close button or Escape closes it and returns focus to the button, and nothing under the sheet takes that tap. The search button and GitHub are 44 px to press, the pages 32 px, with the text where it was. The gutters follow a notch on a phone held sideways (`viewport-fit=cover`, `--safe`); the violet bands still reach both edges.

The footer, on every page: the criteria's standing (a link to the criteria page), the RFC it cites and `criteria.json` with its sha256; then the release (a link to `/release`, "(candidate)" until its publication is recorded), the release's `index.json` (its path as text until #146 publishes it, then a link), sponsors and conflicts (`/sponsors`) and the licence.

### Search

Systems are reached by search, not by one nav link each, since there will be many. The build writes `search.json` (linked by its hash, `search_entries` in `draw/outputs.py`): every benchmarked system, reference, not-benchmarked system and property (the pages are in the nav), with a line of context, its pie and the words it is found by: its name, models, kind and status, its stated technique, its code status ("no public code", "closed source"), its badge, and a few words true of its whole family (`TERMS`: "zk", "TEE", "enclave"...; how a system proves, STARK or SNARK, comes only from its own stated technique). People's names are not indexed.

`words.js` loads it on first focus and matches locally (nothing leaves the browser): the start of a name, a word in the name, then the other words. A typo (a letter added, missing or wrong, or two swapped) is tried only for a word no entry has, and only from its right first letter. A number glued to a word is apart ("llama4" is "llama 4"); one letter searches names only.

Not-benchmarked systems come after every other match, each marked "Not benchmarked" (most are closed source, so they cannot be run here). Within each part results are ordered by where the words matched, then by kind of entry (benchmarked systems, properties, references), then by closeness. Up to 12 of each part are listed, and a line counts the rest. A not-benchmarked result leads to its card in the overview, marked and labelled "Not benchmarked". An empty field lists the benchmarked systems.

On phones a result keeps its badge on its name's line and its line of context under both, at full width, cut after two lines. A touch on a result does not cancel its press (WebKit then drops the click); the field's blur is let pass once instead.

`/` or Ctrl/Cmd + K focuses it from anywhere (`aria-keyshortcuts`); arrows choose, Enter goes to the chosen result or the first of a typed search, Escape clears then closes. It is an ARIA combobox with a listbox; the count is announced; without script it is not shown. If `search.json` cannot load, the list says so and the next focus tries again.

### Overview

1. A plain legend on the violet field: six small key glyphs (each property's own triangle in ground ink, 5.92:1 on violet, the other five faint), each property's name and question, the states key and the link to the criteria page. Nothing in it reacts to the pointer. On phones (560 px and below) it is a 2 x 3 key of glyph and name, 1 and 2 on the first row, its two columns sized by their names so each name keeps one line from 375 px; the questions are read to screen readers there and shown on the criteria page, so the first system shows on landing. On a phone held sideways it folds into three short columns so the first table's heading shows on landing.
2. One section per model, largest first by total parameters (**Llama 4 Maverick**, 400B, then **Llama 3.1 8B**, 8.03B), each system in it once and in no other, under the header "Native workloads differ: rows are not a head-to-head comparison": the model's name, its size and workload in one line (one fact per line on phones), and a sortable table of the systems on it (glyph, name and pin, then One proof covers, Proof size, Check time, Overhead). Each figure links to its plate on the system page and shows its sample size and range when it has them. Each figure link is named after its column for screen readers, also where the column heads are out of view.
3. **References**, after the models: two rows, plain serving and a rerun by a weights holder, on the same columns, exposed as a table through ARIA roles (heads, row headers, cells). Not sorted. Their figures link to the reference's own plates.
4. **Not benchmarked yet**: a compact grid, A to Z, of glyph, name, models and status.

Pointing at a row's triangle with a mouse lifts it (the others keep their ink) and shows its name and state under the glyph. A still copy of the triangles takes the pointer, so a lifted one never flickers out from under it. On a touch screen the first tap on a triangle does the same, and a second tap on it follows the link; a tap elsewhere clears it. Hover effects (a figure's underline, the name's arrow, a lifted slice) apply only where there is hover, so a tapped element does not stay marked after Back.

Each home figure links to its own plate: `/<system>#fig-<column>` on a system page, `/reference#<reference>-fig-<column>` on the reference page. Each system row's header (its glyph and name) links its card's validated claims, `/<system>#claims-<configuration>`.

Below 920 px both tables become a board: each row is two lines, the glyph (52 px, 40 px on phones) beside the name and pin, then the four figures in columns that line up with the heads from row to row, so a column reads down like a leaderboard and a 390 px screen holds about five systems. Each figure's label is the head above it; the cell still names its column for screen readers. On phones (560 px and below) the figures are smaller and the run counts and ranges under them are left to the system page (still read aloud and in each figure's tooltip). The references' heads show above their columns there too. The Not benchmarked yet entries are compact (44 px glyph), in one track, and the last entry's rule closes the grid, so the footer draws none below 636 px.

### Sorting

The column heads are the only sort control, and one order applies to every model's table. It reorders the rows within each table: the tables keep their model-size order and each row stays in its own table. Each head is a button with a glyph: ↕ idle, ↑ or ↓ when it sorts, a second press reverses. The sorting head is in paper with a rule under it and its cell has `aria-sort`; the order is also named for screen readers ("Proof size, large to small", from the direction words, `SORT_WORDS` in `draw/plates.py`). Below 920 px the heads sit over the board: System on its own line, then the four figure heads, each above its own column, buttons 32 px tall or more. When a figure column sorts, its figures stay in paper and the other three turn muted, so the sorted column reads down the board. A head that wraps keeps its glyph beside its last word (a no-break space). Without script the heads do not look pressable.

- The order is kept in the hash: `#sort=proof_size-desc`. The default (System, A to Z) has no hash; an unknown order falls back to it, and so does going Back to the page without a hash.
- A figure with no number goes last in both directions. Ties fall back to the name.
- Rows move in 200 ms (FLIP), at once under reduced motion.
- Neutral: no rank numbers, medals or ranking words.

Sort keys are the stored values, never typed or parsed back from a printed figure: each row's `data-k` holds, per column, the value the release's `index.json` stores for that statistic in its base unit (token, B, s, ratio), or null. The printed figure is that value at 4 significant digits, scaled for reading (MB, ms, min). `test_sort_keys.py` checks the keys against the stored values and hand-computed cases from the placeholder release.

### System pages

The violet band holds the name. Below it, the card's validated claims, under the anchor `claims-<configuration>` that every overview row header links (RFC-0009 S1; following that link shows the page from its top, the name in view): the pie (200 px) in the middle with each property beside its own slice, slices 1 to 3 on its right and 4 to 6 on its left, top to bottom, each text beside its own triangle (the composition before #320, row gap 18 px). Each property shows its name (a link to what its states mean), state and our short reason (left out when it only repeats Not stated); its question is read to screen readers. After the reason, a small muted "source" link (mono, underlined, like a rule link; read aloud as "source: how we read <property>") to the property's entry in "How we read it" (`#read-<property>`); with no reason, the link stands alone under the state. For an overridden cell, one more line under it, one line long: the stated state and each control that contradicts it, then "accepted in run", the run a link to the property's entry, whose control line prints the run id with its record (RFC-0016 OVR-7). That is the one line that changes the state. A run id is longer than the column beside a triangle, and wrapped it would push the other properties off their triangles; a screen reader hears the id in the link. Nothing else sits beside the glyph. A stated cell with no deciding quote, or a deciding quote with no repository, commit or link, stops the build. Under the properties, folded in a native `details` ("How we read it", one press opens it, with or without script) in the style of the card in full, one ruled entry per property (id `read-<property>`) that has any of: the quote marked `decides` in the criteria file, verbatim with its line breaks and in quotation marks, with its source at the pin (`repository@commit path Lx-Ly`, the repository without its owner, which the facts' pinned row and the link's title name; an underlined link to the file at that commit, its arrow held to the last part); in a conflict, every quote instead, each with the state whose rule it meets and its source; the sources read, one line per repository linked at its commit with the paths read (a path never breaks inside), or "as for <property>" (linked) when a property above read the same; and the controls RFC-0016 ties to the property, with their outcome in every run read, one line per run that recorded them and one line naming the runs that did not ("not run", then each run on a line of its own), or "none" with a rule link. With no run read, the line says why ("no run read, since the criteria file names no release", RFC-0016 OVR-5), so it never reads as a run that skipped them. Each line carries a quiet label in a column of its own ("quote", "yes", "partly", "no", "read", "controls"). Under a pending disclosure (OVR-8) no control line and no overridden line is printed; the quotes and sources read stay. A "source" link, or an address naming an entry, opens the fold and moves focus to the entry (`words.js`, which only reveals: RFC-0009 S10; a press that opens a new tab leaves the page as it is). The entry the address names has its name lit and underlined (`:target`), so a click inside an entry marks nothing. Without script, Chromium, Firefox and WebKit open the fold on the entry by themselves. "How we read it" stays in the validated claims in reading order (RFC-0009 S1 item 1), before the card's identity: at 1240 px and up it runs full width under the pie and the facts, directly above the card in full, so the two folds read as a pair; below, under the properties and above the facts, opening on its rule, which the facts' first rule closes. Pointing at a property lifts its slice; pointing at a slice marks its property. Beside the pie, the facts, the pie keeping to their top: the card (its configuration and version, a link to the card file, the first 12 hex of its sha256 and "card not reviewed by system maintainers" while no maintainer reviewed it; one run of text on phones), kind, model, pinned repositories, licence, status (one form for every system: the state, then its last push and source when stored), adapter notes. Below 1240 px the facts move under the properties and "How we read it". At 760 px and below the glyph appears once, as wide as the page allows (up to 340 px), and each triangle carries its property's name in ground ink (never its state: the ink says it). A slanted side carries its name along it, the longer line nearer the side; an upright side, level, against it (`_names_svg` in `draw/hexagon.py`). Under it, one ruled row per property, clockwise from twelve: the name as a quiet label, the state with its square in one column, the reason as a muted second line ending in its "source" link. A tapped triangle lifts with its name, and its row takes a ground of its own. On a touch screen a tap on a slice or on a property (not its link) lifts the slice and marks the property, as pointing does; the property names are underlined there. On a phone held sideways the band is shorter and the pie 160 px, so the whole glyph and the first property show on landing.

Then the claim card in full, folded in a native `details` ("Claim card in full", one press opens it, with or without script): every field as stored, each source under the field or list item it is keyed to (`repository@commit path Lx-Ly`), a key that names no field of the card labelled with its own name; on phones a nested field is indented by a rule. Under it, open, "Quality gap and residual": the card's `quality_gap` and `residual` ("not stated" where the card holds none), in the muted evidence style with each item's source under it, and the agreement rate with a rerun on a plate beside them (RFC-0015 RC-6), every label in view or why it has no value.

Then the figures: what they are over, the runs left out of them by id with their status (failed with its kind, step, exit code and last line; superseded with its reason, then the run that replaced it; left out with the reason the index records), four plates, each with its own id, `fig-<column>`, with every label: spread, scope, grade, checked, workload, why, source; their rules line up across the plates, and more numbers in a table (each row with its spread: completed and failed counts, range, mean and sd, then scope, grade, checked and source). Then the tamper tests: each stored outcome count of the configuration, named by its configuration, workload, division and profile, every outcome outside its control's expected set printed in full from its record (control, run, outcome, expected set, side, source, honest twin, any other stored field, each trial with every field under its stored name, its mutation included, note, record; id `unexpected-<control>-<run>`), then the control tests the system registers (`systems/<system>/controls.yaml`) with their outcome. Then the system maintainers' reply, when the release lists one (`#reply`). The reference page uses the same layout for each reference, with one set of figures, headed with the reference's name ("Figures · Plain serving"); each overview figure of a reference links its own plate there (`<reference>-fig-<column>`). On phones a plate's label sits beside its value from 350 px (stacked below, where a source path's parts no longer fit), plates are parted by one rule, and the reference page pairs its plates. Links on these pages and in the footer have hit areas 24 px tall or more that move no text.

### Release, sponsors and conflicts, targets

`/release`: the release record as ruled rows (release and whether it is a candidate, freeze date and review window ("not set" while a candidate, see Open), the RFCs at the release's `rfc_commit`, reference file, harness version, the index's path, systems, claim cards with their digests, replies, targets), then every run the release lists, grouped by system, workload and profile, each by id with its status, the withdrawn runs with their reasons, what checked each configuration (its tier and the review and reproduction records), and every control outcome outside its expected set, linked to where its system page prints it in full (under a pending disclosure, the RFC-0008 notice only). `/sponsors`: the sponsors `release.yaml` lists, then every row of `MAINTAINERS.md` with its role, organisation, systems, declared interests and date. `/targets`, only when the release evaluates a target: each target with its author, date, threshold and labels, rationale and file, then each row it was evaluated against with its result, mean and least favourable value, each with every label and its record in the index. These pages are not in the nav or in search; every footer links the release and sponsors pages, and the release page links the targets.

### Criteria page

`/criteria`: for each property, its name and question, then what Yes, Partly, No and Not stated mean for it, and what it does not cover, from `criteria.json`. Below 1000 px the states go under the name; at 760 px and below an index of the six properties (key glyph and name) sits under the band and jumps to each; at 560 px and below each state's word sits over its definition at full width. The nav, the legend, the footer and every property name on a system page link to it.

### Preview cards

What a shared link shows (Open Graph and X `summary_large_image`): every page carries its title, description, canonical URL and a picture with its alt text, all from the view. The pictures are 1200 x 630 at 2x (2400 x 1260 PNG) and drawn in the site's own type and inks:

- `og/home.png` (the home, the reference and the criteria page): only what does not change with the systems benchmarked, since link previews stay cached in message apps for as long as the message lives: the six property names on the violet field, each beside its place in the pie, and the site's mark and name. No system, model or state.
- `og/<system>.png`: the system page's first screen: the name on the violet band with its model and pin, then its pie with each property's state beside its own slice.
- A system card says "Draft criteria, needs an RFC" (the criteria label), since a picture travels without the page around it. The alt text says what the picture draws.
- `og/icon.svg` (the favicon) and `og/icon.png` (the 180 px touch icon, rendered from `og/icon.html`): the hex asterisk in ground ink on the violet field.

No figures are drawn: results are placeholders until a release exists, and a picture travels without its labels. The build writes each picture's source (`og/<card>.html`); `og.mjs` renders it with the same Playwright as `shoot.mjs`, with the fonts from `fonts/` (no network), refuses a card whose fonts did not load, whose content spills past its edges or whose system name runs into the band's corner text, and records the sha256 of source and picture in `og/cards.json`. The pages name each picture with `?v=` and the first 12 hex of its hash, so a new picture is a new URL for link-preview caches. `test_cards.py` fails when a committed picture was not rendered from its committed source.

### 404

An unknown address answers the site's own page with status 404: the header and the violet band, "Not found". Up to 960 px its header shows the search field open under the pages (not focused, so no keyboard on load). It is never shared (`noindex`, no preview card).

### Accessibility

axe passes on every page at 1440 and 390 px (WCAG 2.2 AA and axe's `best-practice` rules). Beyond it: no duplicate ids, row headings hold only the system's name (its six states follow as text for screen readers), arrows are not read aloud, page titles carry the site's name, the band's name keeps every letter under text-spacing overrides, nothing overflows at 320 px (400 % zoom), and under forced colours (Windows high contrast) the state squares keep their inks and Not stated stays empty.

## Files

- `build.py`: the renderer's entry point, which `iproofs site build` loads and hands the view: `setup` reads the view into the build's state and runs the checks, `check_stale` stops on a page or card source the build no longer writes, `render` writes the files. ## Open

- Each model's table holds one system, so sorting within a table moves no row until a second system runs a model's workload (the shared Llama 3.1 8B workload, #334).
- A system that runs two workloads (its native one and the shared closed one, say) has a row in each workload's table, so it is on the overview twice; the extras build shows this (SASH, FlashProve). The deployed placeholder runs each system on one workload, so each is on the overview once. Whether a second workload's row should fold into the first is the owner's to decide (RFC-0009 Q5, #333); folding would put a closed workload's figures in a native table, which RFC-0003 §Divisions does not allow.
- The pie's states come from reading each system's documentation at its pin (the criteria in `criteria.json`), not contradicted by the controls the release ran (RFC-0016): a negative control accepted where RFC-0008 expects rejection sets No on Model bound or Whole output checked (CRIT-13), and no control tests the other four properties. The reason line is ours; the deciding quote under it is the system's. The data does not yet mark a cell whose sources were not read (`not_copied`, RFC-0016 Q2) apart from silence on the page (#319).
- `load_criteria` keys each card row by its card (RFC-0016 migration item 9), but the renderer still draws one glyph per system page and finds a card row by its system id: a system that runs two card configurations, or a card row whose id is not its system, stops the build (`check_rows`).
- The system page prints each cell's deciding quote, or both quotes of a conflict, in "How we read it", and no other quote: a cell's supporting, `aside` and `outside_pin` quotes and its `note` are not printed on any page (RFC-0016 OVR-7; RFC-0009 §Site gaps).
- The direction words (`SORT_WORDS` in `draw/plates.py`) mix two patterns ("small to large", "fewer positions first").
- The release's `index.json` and its run records are not published until #146, so each figure names its record as a pointer in text, and each run left out names its id, not a link to its record.
- Waiting for the owner's sign-off, since they change the overview's look (RFC-0009 S6, S1): a heading per native workload table naming its workload, division and profile (closed and open tables have one), and a note in Not benchmarked yet that its states come from public sources.
- The system page's reference rows on the same workload (RFC-0009 page table) are not printed; the reference page holds them.
- Also left for later (RFC-0009 §Site gaps): a heading per configuration naming its workload, division and profile when a system has one configuration; the reply beside every overridden cell (RFC-0016 OVR-6) and "not reviewed by system maintainers" beside it; one link per RFC on `/release`.
- While the release is a candidate, `/release` prints its freeze date and review window, and `/sponsors` its sponsors, as "not set: v0.1 is not frozen (#146)": the placeholder's values are a test fixture's, and the README's placeholder policy covers benchmark results only.
