# The public site

The public site at www.inferenceproofs.ai, its design named "The instrument" (in the brand "Made of words"), served with `noindex`. The rules it follows are RFC-0018 §Site (SI-1 to SI-7).

Pages, written by `iproofs site build` and served at clean addresses: `/` (the ladder), `/scale` (every row on a decade axis), one page per row of the board (`/<system>`, or `/<system>-<model>` for a system on more than one model), `/checks` (the six checks, the order rule, what is not tested), `/mandate`, the Learn pages (`/learn`, one page per entry of `learn/index.yaml`, `/glossary`) and the 404 page. Addresses of the earlier site (`/criteria`, `/reference`, `/release`, a level system with no page yet) redirect.

## Build and check

From the repository root:

```
uv run iproofs site build                                   # into web/, from the newest releases/v1.*/board.json, or the level file alone
uv run iproofs site build --board PATH --out DIR            # a preview from a given board file
uv run pytest web -q                                        # figures, states and order against the board file
```

The build writes the pages, 404.html, search.json, vercel.json, the card sources in og/, the fonts block in words.css and the contrast table below; `--out DIR` writes a complete site elsewhere (static assets copied). It never deletes a file: a page it no longer writes stops the build. `python3 -I serve.py` serves this folder at http://127.0.0.1:4440/ under `vercel.json`'s rules; `PLAYWRIGHT_MODULE=<path to playwright/index.mjs> node og.mjs` renders the card sources to og/*.png (`OG_CHANNEL=chrome` runs an installed Chrome instead of Playwright's own browser; then rebuild, so the pages name the new pictures). When the display font file changes, `<python with fonttools and uharfbuzz> -I wordmark.py` redraws the wordmark's outlines from it (`fonts/wordmark.json`); the build stops while they name another file.

## Deploy

Vercel serves this folder (Root Directory `web`) as committed: `buildCommand` copies the pages, `words.css`, `words.js`, `search.json`, the pictures and the fonts into `public/`. The build writes `vercel.json` (redirects, a Content-Security-Policy allowing the one inline script by its sha256, cache rules). `.github/workflows/site.yml` rebuilds the pages on every change to an input and fails if any file under `web/` differs from what the build writes.

## Data

`iproofs site build` reads `levels/L1.yaml`, the newest Level 1 release's `releases/<release>/board.json` (schema `board/1`; or the file `--board` names), the claim cards `systems/<system>/claim.yaml`, `_data/facts.json` (schema `site-facts/1`: names, licences, who builds the site and its members (`credit`), and each system's one fixed reason when it has no row, SI-4) and the Learn pages' words, `learn/` (below). With no Level 1 board, every rung of the level file is drawn as not run yet. `iproofs.site` turns these into one view with no git call and no clock; the renderer (`build.py` and `draw/`) draws that view and opens no data file. Every printed figure is a `quantity/1` value of the board file, printed at four significant digits in a reading unit, with its labels and record (the board file and JSON Pointer) in its title; its scope and n are printed under it on a system's page (its band, Cost, Fidelity) and on the Learn pages, not on the overview or the Scale page (AGENTS.md rule 2, RFC-0018 SI-8). The renderer types no number. `_data/criteria.json` (RFC-0016) no longer drives the site; no figure of v0.1 is printed (SI-5).

## Design

What goes on which page is decided by depth: the surface shows results, each step down shows more of how they were taken. [`DEPTH.md`](DEPTH.md) is the map (the depths, what goes where, how words change with depth, a test for a new line, the known gaps); RFC-0018 SI-8 is the rule. Read it before adding a line to a page.

The name is set as a formula, INFERENCE ⊢ PROOFS: capitals in Big Shoulders Display 900 (in outline, `fonts/wordmark.json`), the mark between the two words at cap height. The mark is the turnstile ⊢ on a grid of 20 by 15 units (1 unit = cap height / 15): a solid stem 3 units wide, and on its centre line three square cells of 5 units with gaps of 1, the first joined to the stem. In the lockup it stands 4 units after the E and 3 before the P. Below 32 px it is redrawn on whole pixels (13 by 9 px at 16, doubled at 32). It is the header's logo, the icon (`og/icon.svg`, the touch icon and the 32 px PNG: the mark in ground ink on cobalt) and a page's mark in search results. `draw/mark.py` draws all of it.

An instrument, made of words: the site is operated, not read. Dark ground `#0b0b0c`, paper text `#f1efe9`, muted `#9b978e`, rules `#6f6a62`, lift `#17171a` (the ground under the row in hand), and one flat cobalt `#5b7bff` for the benchmark's own frame: the band (black type on it), the mark, the tab and section in view, the row in hand, focus, an arrival; never a value or a state. The state inks fill the petals and the state chips (ground type on green, amber or red; undecided and hollow an outline). No gradient, glow or drop shadow. Names, titles and positions in Big Shoulders Display (800, 900); every label and figure in Martian Mono (400 to 600, width 87.5), on a short locked scale. A page's title (Checks, Mandate, Not found, a Learn page) is set at the home title's size (`--title`); only a system's name on its band is larger. Both faces are served from `fonts/` with their licences (`OFL-BigShoulders.txt`, `OFL-MartianMono.txt`); Martian Mono shows a system monospace after 100 ms while it loads, Big Shoulders waits for its own file. Grids of cells share hairlines that meet; there is no stem.

What stays in view: the top bar (lockup, the tabs Ladder, Scale, Learn, Checks and Mandate, search, GitHub; a system page marks Ladder and a Learn page marks Learn; Learn only when the tree holds the Learn words; on a phone in two lines, the tabs 44 px tall, stepping away on the way down and back on the way up (a jump to an anchor sets it first, so the anchor lands right under what stays), and the same step-away on a phone held sideways, which also gets the 16 px field and a list that ends above the keyboard); on the overview each table's heads; on the other pages a strip of the page's sections, the one in view marked (the one whose heading sits right under the strip, else the earliest of those whose heading has passed a third of the window under it and is still under the strip, else the last that has passed; at the page's end the last, unless the section a link went to is in view), the page's title in it once the band is gone (not on a Learn page, whose chapter row and band name it, so every label stays whole; on a phone a label longer than the strip takes two lines). On a touch screen a target is 44 px (an evidence link 26 to 32 px, so a check's list stays a list; a check's "not run", a row's standing and the glossary list 25 to 32 px, between neighbours); the search field is 44 px tall with 16 px words, and on a tablet, in use, the field widens over the tabs to its list's width (420 px), the tabs stepping aside and the list hanging under it. Each section keeps a heading at a modest display size; the first one, right under the strip, is for screen readers only.

The glyph is a row's state, drawn as the turnstile with five arms (RFC-0018 §The glyph): a cobalt stem and one arm per petal (Unforgeable, Weights hidden, Faithful model, Machine-checked, No third party trusted), top to bottom, each arm the petal's name in ground ink on the ink of its state (green, amber or red, a red name struck; hollow an outline, its name in the muted ink). Two steps change the drawing, never the ink (§The glyph, Q7): amber in lesser part is cut (the arm stops one unit short of a 5-unit end cell; the gap never under 2 px, the cell never under 3 px), and a red the publisher is silent on is open (the hollow outline in the red ink, its name red and not struck; on a lifted row the name takes paper, since red on lift is under 4.5:1). Each arm carries its form as a class token after its state (`cut`, `open`) and its step and cause as `data-step` and `data-cause`; the state and step stay words in the row's screen-reader text and the system page's State cell. It follows the mark's units (stem 3, arm 5, gap 1; 3 px a unit on the ladder, 159 by 87 px), every arm has the same length in every state, and under 3 px a unit (the search list, the 404 page) the names are left out. It never carries a state word or a number; on a system page it is drawn once, large, as the heads of the petals' table (each arm in its own row, on the table's stem; the State cell prints the step in words and, for a red or hollow petal, its cause linked to its definition; Machine-checked's Reason cell holds its tool, theorem, trusted base and scope card, Weights hidden's the publisher's list of visible values; the From line in its disclosure adds "our reading" when the board petal's `reading` is true), and on the checks page as the key, in cobalt, each arm a link to its four rules (green, amber in part, amber in lesser part, red). Each arm also carries its ink as SVG attributes, so a glyph reads with no stylesheet. A petal and its line light each other: the petal in hand takes a hard paper edge and the others keep their fill (an outline stays the hollow state's alone); the other lines of the tables dim to the muted ink, their state chips kept whole. On the checks page the key's petal read stays solid and the others turn to cobalt outlines, their names in paper.

Response (motion only with `html.anim`, none under reduced motion; under 250 ms; never on a number, which never shows a value that was not measured): a row, a search result and a 404 cell are press targets, lifted with a cobalt edge when pointed at, wider on focus and press; a tab, a strip link and GitHub fill with cobalt from their bottom edge in 120 ms and empty at once; a footer link turns to cobalt under ground ink at once; the search list unrolls from the field on a hard edge, and the words a result was found by are marked. Arriving on an anchor of the checks page (a petal, a check, a figure, a cause, a rule), its heading is set in a cobalt block that slides in from its left edge (`clip-path`, 240 ms). j and k step through the rows once focus is in the ladder, the arrows from a row (at the first or last row an arrow scrolls the page); the row you came back from stays marked. Pointing at a figure, focusing it from the keyboard or tapping it shows its labels from its title (scope, grade, evidence, n, record) under it, and a petal of a row's glyph its name, its step and, for a red or hollow petal, its cause; a second tap or a tap elsewhere puts them away, a mouse's click keeps them, and in a ladder row or the band's block a tap on a figure shows its labels where a tap anywhere else follows the link. The labels appear where they stand, fading in with no travel. The labels keep to the page's gutters; under a figure (a petal's under its whole glyph), or over it and its name when the window ends first, or beside it when under and over would cover another figure. A mouse can move onto the labels (they go a quarter second after it leaves; moved onto another figure under them, they give way to that figure's), and so onto a glossary term's peek; in a window too short for them they scroll inside (with the arrows, for labels focus showed), and focus first brings the figure up under the bars. A mouse click on a figure's words in a row waits one double-click's time, so a double-click selects them. The labels are the figure's description for a screen reader while shown, and those focus showed follow their figure when the page scrolls, as a glossary term's peek follows its term. Ctrl or Cmd K, or "/" from anywhere but a field, opens search; focusing the field never scrolls the page. Between pages, cross-document view transitions (`@view-transition`): the page swaps at once (the root takes no snapshot, so nothing crossfades); the top bar stays, the tab's bar slides, a row's name morphs into the system page's title and back (the page's glyph is its petals' table, so the row's glyph has nothing to morph into) (between the ladder and a system page only: to or from any other page they swap at once with the rest). On paper the band prints as paper with cobalt rules, the controls are left out and the petals keep their inks, as does every fill that carries words (a size tab, position 1, the system's own replies row); under forced colours the lockup takes the text colour, every petal and swatch an edge (a hollow petal's edge and name the text colour), and focus a line wherever it was a fill.

Script: `words.js` holds search, the row as a target and j/k, the one scroll handler (run once a frame: the strip's section in view and title, the phone's top bar, the key's petal read, putting away the figure labels and a glossary term's peek a pointer showed, and keeping those focus showed beside their figure), the petal lighting, the figure labels and the Learn pages' explorers; what CSS can do alone (hover, press, arrival) is CSS. The one inline script, `HEAD_SCRIPT` in `draw/chrome.py`, runs before the first paint: it adds `html.js`, adds `html.anim` unless the reader asked for reduced motion, and on a page reached by a view transition names the row the reader came back from (so its name morphs back into it) and sets every morph to 200 ms on a quick ease-out. `vercel.json` allows it by its sha256. The stylesheet comes before it, so the `@view-transition` rule is known when a page is revealed. With no script the site reads in full: search is left out and the checks page's key still links each petal.

## The Learn pages

`learn/index.yaml` lists the hub's words, two tracks (for policy readers, for engineers) with their pages in reading order, and the glossary. Each page's text is `learn/<slug>.md`, in a small, strict subset of Markdown that `draw/learn.py` documents and draws: headings, paragraphs, lists, tables, code, links (a site path, `repo:<path>` for a file of the repository, or a URL), `[[term]]` for a link to the glossary entry of that name, and blocks between `:::name` and `:::` (`note`, `stage`, `quote`, `reading`, and the drawn ones, `figure`, `explore`, `measured`). A construct outside the subset, a mark it does not read (a stray `*`, bracket or backtick), a term the glossary lacks, an id used twice, or a dash used as punctuation stops the build. A page's address must not be that of a site page, a redirect or a system: the build stops on a clash. A `stage` block names what stands behind a stage of the treaty page: `measured` (printed as "Run on this site"), `demonstrated`, `proposed` or `outside`.

The rules of the rest of the site hold on these pages. A figure of the board is printed only by a `measured` block or an explorer's presets, through `fig_html`, from the board file, with its labels: the text types none, and a page reads correctly with no board. The text calls such a figure run or recorded, never measured (README, evidence tiers). A publisher's words are quoted, with a link to the line at a pinned commit. The words follow AGENTS.md rule 10 and RFC-0018 SI-5 and SI-6, and `test_learn.py` checks the ones a test can check. The text states Level 1's constants (the request, the margin, the tolerances) in words: reread it when a level changes.

An explorer (`draw/figures.py`) is a figure a reader can operate: the treaty walk, tamper and check, the random check of a matrix product, the sumcheck, the cost of proving a share of replies (generation on every reply, proving on the share: RFC-0018 AD-3, CO-7). The build draws each in full (every step, every case, the worked example, every sentence), so the page reads without script. `words.js` then shows one state at a time and adds the controls. The arithmetic of a worked example is written twice, in `figures.py` and in `words.js`; `test_learn.py` checks the first against hand-computed cases, and the script checks itself against the page when it starts.

How they are drawn: a page's band holds where it stands (Learn, its track; the glossary at the line's right end), its title and summary, and on its lower edge the track's pages as cells, the page in view a block of ground ink that slides to the next page's cell between pages (a view transition). The hub's band holds the two tracks as two cells, each over its column of pages, and under them every term of the glossary. Under a page's band, the chrome's strip of its sections, with at its end the page's place in its track between the page before and the page after. Section titles hang in a margin column beside their first lines; the text keeps a measure of about 72 characters, and drawings and tables take the room to its right. On a phone a table stacks, each cell under its column's head, and the session drawing takes a narrow layout of its own: nothing scrolls sideways. Under the text, the page before (an outline) and the page after (a cobalt block). A glossary link, pointed at or given focus, shows the term's name and first sentence, which the build writes on the link (`data-g`, `data-d`). The glossary sets its terms under their first letter, each letter a section of the strip and kept in view while its terms pass. Arriving on an address sets the heading in a cobalt block that slides in.

The glossary restates the benchmark's own terms in plain words with the meaning `docs/spec/10-glossary.md` gives them, and defines the field's general terms (soundness, zero knowledge, security level) that the specification uses without defining.

## Files

- `build.py`: the renderer's entry point (`setup`, `check_stale`, `render`); it loads `draw/` afresh for every build. `serve.py`: the local preview.
- `draw/`: `state.py` (what `setup` reads), `words.py` (fixed words for stored ids, numbers in reading units, the checks' definitions), `inks.py` (contrast checks), `hexagon.py` (the glyph), `mark.py` (the turnstile, the lockup), `chrome.py` (addresses, fonts, the inline script, the top bar and its tabs, the search field, the section strip, the footer, the page frame, share tags), `overview.py` (the ladder), `pages.py` (system pages, checks, mandate, 404), `scale.py` (the scale page), `plots.py` (the system page's cost bars and fidelity tracks), `figures.py` (what the Learn pages draw: figures, explorers, blocks of board figures), `learn.py` (the Learn pages and the Markdown subset they are written in), `outputs.py` (search.json, vercel.json, the card sources and icon in og/, the fonts block, the contrast table above).
- `learn/`: the Learn pages' words, `index.yaml` and one `.md` file per page (CC BY 4.0, as the documents are).
- `conftest.py`, `test_site.py`, `test_learn.py`: the site built from `harness/tests/fixtures/board/v1.0-example.json` (invented values) and with no board; the Learn pages' subset, links, words and worked examples.
- `words.css`, `words.js`: style and behaviour, no data. `fonts/`: the font files, their licences, `faces.json` and the wordmark's outlines. `wordmark.py`: writes those outlines. `og/`: the card sources, their pictures and `cards.json`. The home card holds the stacked lockup and the address only. A system's card is its page in brief: the top bar's lockup, a cobalt band with the name (one line as large as fits, a long name on two) and its model with its size, the band's one figure on the right (set light with no position, as on the page), then the standing as large as a name, cost and verify time per reply, the glyph with its names, the release and the page's address; every figure with its unit alone, under its plain name (a card is shallower than the ladder, `DEPTH.md`). The band prints the multiple's two parts under the figure. The picture's alt text says what it shows: the system, its model, the band's figure, the standing, cost and verify time per reply and the petals, each figure with its unit. `og.mjs` renders each source to its picture, records both sha256 in `cards.json`, and stops on a card whose words run past their box or whose blocks overlap. A page whose picture is missing, or was rendered from another source than the one the build just wrote, names the home card and offers no card download. After a board change: `uv run iproofs site build`, then `OG_CHANNEL=chrome PLAYWRIGHT_MODULE=<path to playwright/index.mjs> node og.mjs`, then `uv run iproofs site build` again. A system page's share group (the strip's right end; the band's facts on a phone) holds the card as a plain download and Copy link, which `words.js` shows and which copies the page's canonical address. `og/members.html`, a picture for posts with the members' names, is written once `credit.members` lists any. `_data/`: `facts.json` and `criteria.json`.
