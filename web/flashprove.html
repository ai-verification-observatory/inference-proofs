    FlashProve

    What one proof establishes

    1. Weights hidden. Does the checker learn nothing about the weights?

      Partly

      Hidden by design, but one bit per request leaks.

    2. Model bound. Is each checked token tied to the committed weights?

      Partly

      Only under exact match; the expected use checks just the client's limits.

    3. Whole output proved. Does one check cover every output token of a request?

      Partly

      Covers the positions the client names; completeness of the reply not shown.

    4. Formally verified. Is the security argument checked by a proof assistant?

      Yes

      Soundness and zero knowledge proved in Lean for the protocol; the C++ verifier and CUDA prover are tested, not proved.

    5. Security level. Is a soundness level stated, and proven?

      Yes

      Bound stated and proved in Lean for the protocol, in the random-oracle model.

    6. No trusted party. Does a check hold without trusting a chip maker, a setup ceremony or an honest party?

      Partly

      You must grant its public files were fixed before the hash.
