  1. Weights hidden

    Does the checker learn nothing about the weights?

    Not stated

    Silent in the 15 sources read

    Our note · Outside the pin, SASH's own note says: Partly (not counted)

    • Our note: no passage says whether a proof hides the weights. Two passages come near and were not copied into this slot because neither states it: the verifier compares the model root with a published manifest because "it commits weights the verifier does not hold" (zk-inference-prover docs/decisions/2026-09-09-the-verifier-derives-the-shape-root.md L10-L12), and the model's shape is "things the verifier knows rather than things the proof hides" (zk-inference-results docs/statement-gap.md L172-L175).

    • Partly · Hidden behind a commitment; the proof adds no blinding.

      “The proofs are not yet zero-knowledge in the formal sense: the weights are hidden behind a commitment, but the proof system adds no blinding.”
      SASH research note (September 2026), outside the pinned repositories ↗

  2. Model bound

    Is each checked token tied to the committed weights?

    Yes

    Each matrix product checked against pinned weights; each token is the top choice.

    “each matmul's input times the pinned weights into its accumulator | bound | nothing: it is the Freivalds check itself”
    docs/statement.md L32 · eb95bfa8 ↗
    More quotes · Our note
    • “the argmax binds the token a head segment emits to the lowest-indexed maximum of the logits it computed, which is the rule the model itself decodes by.”
      docs/statement.md L147-L149 · eb95bfa8 ↗

    • Which real model: 'which model that root is, is the statement's own assertion until a published commitment is compared with it.' (zk-inference-results REPRODUCE.md L1406-L1409).

  3. Whole output proved

    Does one check cover every output token of a request?

    Yes

    One statement per request: every prompt position and the whole continuation.

    “The prover proves one end-to-end statement about one request: every position of a prompt and of a 512-token greedy continuation, from the embedding up through every layer and through the output head”
    docs/statement-gap.md L3-L7 · 11decec3 ↗
    More quotes · Our note
    • “A sequence is proved as a grid of such segments, and boundary-grid checks that the segments fit together.”
      docs/statement.md L5-L7 · eb95bfa8 ↗

    • The request is checked as a grid of segment proofs joined by boundary-grid; the benchmark counts the grid as one proof (systems/sash/README.md).

  4. Formally verified

    Is the security argument checked by a proof assistant?

    Not stated

    Silent in the 2 sources read

    Our note · Outside the pin, SASH's own note says: No (not counted)

    • Searched for: machine-checked, machine checked, formal, Lean, Coq, audit, human review, soundness. docs/statement.md argues each edge in prose; no passage says how that argument is checked.

    • No · Soundness evidence named: human review and negative controls.

      “our soundness evidence is human review and negative controls.”
      SASH research note (September 2026), outside the pinned repositories ↗

  5. Security level

    Is a soundness level stated, and proven?

    Partly

    Level stated as conjectured, in a source code comment.

    “stwo's own conjectured-soundness accounting is security_bits = pow_bits + log_blowup_factor * n_queries so blowup 2 (log_blowup_factor = 1) at 100 conjectured bits means exactly 100 FRI queries and no grinding.”
    prover/src/util.rs L9-L12 · eb95bfa8 ↗
    Our note

    • The documentation names the security block only as '`security` (the FRI parameters and the hash)' (prover/README.md L324).

  6. No trusted party

    Does a check hold without trusting a chip maker, a setup ceremony or an honest party?

    Not stated

    Silent in the 15 sources read

    Our note

    • Our note: SASH uses "assumption" only for cost-model inputs, never for what a proof rests on. Passages that name what the verifier takes as input were not copied here, because calling them assumptions would be our inference: `boundary-grid --verify` demands the calibration manifest and `--prompt` (prover/README.md L49-L52), and the model root "stays a comparison against the same manifest" (prover/README.md L56-L59). The source comment under the security notion speaks of "conjectured" soundness.
