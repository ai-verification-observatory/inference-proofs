    What one proof establishes

    1. Weights hidden. Does the checker learn nothing about the weights?

      Not stated: how we read Weights hidden

    2. Model bound. Is each checked token tied to the committed weights?

      Yes

      Each matrix product checked against pinned weights; each token is the top choice.: how we read Model bound

    3. Whole output checked. Does one check cover every output token of a request?

      No

      Every prompt and generated position is checked across the joined grid of segment proofs.: how we read Whole output checked

      statedYes; C2 accepted in run 2026-11-25-sash-sash-l31-8b-c1024-prover-h100-3

    4. Formally verified. Is the security argument for this configuration checked by a proof assistant?

      Not stated

      docs/statement.md argues each edge in prose; no passage says how that argument is checked.: how we read Formally verified

    5. Security level. Is a soundness level stated for this configuration, and proven?

      Partly

      Level stated as conjectured, in a source code comment.: how we read Security level

    6. No trusted party. Does a check hold without trusting a chip maker, a setup ceremony or an honest party?

      Partly

      The fixed statement is produced at setup and trusted by the verifier.: how we read No trusted party

    weight bits
    8 bits per active weight, stated by the system, for part of the active weights ↗
    note
    SASH's own statement covers weight matmuls: exact int8 x int8 accumulations, one scale per output channel. The 8 is the int8 code alone; the per-output-channel scale is not counted in it. SASH states no width for the embedding table or the RMSNorm weights, which active_per_token counts, so it covers part of the active weights. SASH quantizes the pinned BF16 files at load time, so file size (2 bytes per parameter) does not give the proved width. rule RFC-0003 WB-1 ↗
    limit
    Attention cost grows with prompt length and is not in this normaliser, so two workloads of one model with different prompt lengths differ for that reason too (every workload of this release has a 1,024-token prompt). Weight bits are as the workload records them, with their basis and source.
