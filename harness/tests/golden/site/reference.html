    Rerun by a weights holder

    Someone reruns the work: a referee settles a dispute between providers, or a checker holding the weights reruns it.

    What one proof establishes

    1. Weights hidden. Does the checker learn nothing about the weights?

      No

      The checker holds the weights: a rerun needs them.

    2. Model bound. Is each checked token tied to the committed weights?

      Yes

      Reruns the pinned model files and compares every claimed token.

    3. Whole output checked. Does one check cover every output token of a request?

      Yes

      One forward pass over prompt plus every claimed output token.

    4. Formally verified. Is the security argument for this configuration checked by a proof assistant?

      No

      By definition: a rerun, not a proof, so there is no security argument.

    5. Security level. Is a soundness level stated for this configuration, and proven?

      No

      By definition: a rerun, not a proof, so there is no soundness level.

    6. No trusted party. Does a check hold without trusting a chip maker, a setup ceremony or an honest party?

      Yes

      By definition: the checker reruns the model itself and trusts no other party.
